# 停用、卸载与恢复

以下步骤由用户在合适时机执行；停止代理会中断仍依赖它的 Agent。不要自动查杀占用端口的未知进程。

1. 结束本次 Agent 工作，退出由接入命令启动的 Agent/专用终端。新开普通终端，核对启动文件中是否曾手动加入 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、对应小写变量、`NO_PROXY`、`NODE_EXTRA_CA_CERTS`、`SSL_CERT_FILE`、`REQUESTS_CA_BUNDLE`、`CURL_CA_BUNDLE`。只删除自己为 PromptLens 增加的行，不覆盖已有企业代理和证书配置。
2. 若手动修改过 Agent 的 proxy 设置，将其恢复为接入前记录的值。若使用旧 `set_proxy.sh`，它没有保存原始系统设置，无法自动恢复；请到 macOS 系统设置 → 网络 → 当前网络服务 → 详细信息 → 代理，逐项对照原设置恢复。没有原记录时，向网络管理员核实，不能假设原端口为 7890。当前脚本仅支持只读 `status`。
3. 在设置 → 隐私与证书保存 CA 的 SHA-256 指纹。打开“钥匙串访问”，在登录钥匙串中找到该证书，展开详细信息核对完整指纹。确认没有其他工具使用同一 CA 后，仅删除匹配证书/对应信任设置；如果曾手动装入系统钥匙串，也在该位置核对并撤销。不要按名称批量删除证书。Windows 使用当前用户证书管理器的“受信任的根证书颁发机构”；Linux 撤销自己安装的证书并按发行版说明刷新信任库。
4. 从应用菜单/托盘选择退出（关窗口可能只是隐藏到托盘）。将应用移到废纸篓或删除源码副本。应用删除不会移除证书信任或用户数据。
5. 如需删除审计数据，先确认是否需要私有备份，退出应用后在 Finder 中前往 `~/.prompt-lens/`，核对内容并删除这个项目的数据目录。不要把数据库、CA 私钥或重试缓存上传到 Issue。Electron 的用户数据通常在 macOS `~/Library/Application Support/PromptLens` 或开发环境应用名称对应目录，按实际目录核实；不按通配符删除其他应用数据。
6. 用正常 Agent 启动方式验证网络恢复。若仍失败，检查残留环境/Agent 设置/系统代理，勿关闭 TLS 验证。

## 证书损坏或过期

先退出相关 Agent 和 PromptLens，记录旧指纹并按上面步骤撤销旧信任。将 `~/.prompt-lens/` 整体做仅自己可读的备份，避免误删数据库；再手动移开其中 CA 相关文件（`ssl/certs/ca.pem`、`ssl/keys/ca.private.key`、`ca.crt`、`agent-ca-bundle.pem`）。下一次启动才会生成新 CA；核对新指纹并重新配置需要它的 Agent。不要只删除私钥或证书之一，也不要在代理运行中更换。

本轮自动化不对真实钥匙串、系统代理或个人数据执行这些步骤；正式发行必须在干净测试账户中完成安装、撤销与恢复验收。
